# 内容语气转换器：少样本示例

本文件为四模式各提供两组 before/after 对照，用于在执行转换前对齐语气预期。after 文本即本技能应产出的风格样板。

---

## 模式一：技术文档转友好叙事

### 示例 1

**Before**
本系统采用微服务架构，通过 API Gateway 进行服务路由与鉴权，各服务经容器化部署于 Kubernetes 集群，利用 Istio 实现流量治理。

**After**
这套系统把功能拆成了一个个小服务，像一支分工明确的团队。一个叫网关的"前台"负责辨认谁有权进来、该去哪个窗口办事。所有服务都装进标准化的容器里运行，由 Kubernetes 统一调度，就像物业安排每间办公室的用途。至于不同服务之间怎么分配访问量、怎么限流，交给 Istio 这位"交通指挥"来处理。所以这意味着：任何一部分出问题，都不会拖垮整体。

### 示例 2

**Before**
Redis 是基于内存的键值数据库，支持持久化与发布订阅，常用于缓存与会话存储。

**After**
Redis 像个放在手边的记事本，数据存在内存里，所以读取极快。它用"键对应值"的方式记东西，比如用用户 ID 查资料一查就中。它也能把内容存到硬盘以防断电丢失，还能让多个程序同时收到更新通知。所以这意味着：把频繁要用、又不常变的数据交给它，系统就能少跑数据库、快出结果。

## 模式二：口语闲聊转正式报告

### 示例 1

**Before**

**After**

# 客户需求跟进汇报

**背景**：上周与客户沟通，对方提出希望系统支持数据导出功能。

**当前状态**：该需求合理，已纳入本周计划启动开发。

**下一步**：需与后端确认接口可行性，明确排期后反馈客户。

### 示例 2

**Before**
今天开会说了一下推广的事，大家觉得投信息流还行，但是预算有点紧，先小范围试，有效果再说。

**After**

# 推广方案沟通纪要

**背景**：今日会议讨论渠道推广策略。

**当前状态**：团队倾向信息流投放，但受预算约束。

**下一步**：先以小预算开展小范围测试，依据转化效果再决定是否放量。

## 模式四：嵌入写作规范润色

### 示例 1

**Before**
短视频的火爆不是因为内容质量高，而是因为算法推荐。所以我们必须抛弃传统创作方式。

**After**
短视频的走红与算法推荐密不可分。算法把更对胃口的内容推到用户面前，放大了短平快内容的传播，但同样的分发机制也在扶持知识、纪录类等慢内容。传统创作方式不必全盘抛弃，更务实的做法是理解这套分发逻辑，让好内容被看见。

*本次调整：删除"不是……而是"翻案句式；将绝对化判断改为辩证表述；保留原意。*

### 示例 2

**Before**
根据研究——运动对健康极其重要。建议大家每天跑步，这能彻底解决亚健康。

**After**
研究显示，规律运动与更好的心肺功能、情绪状态相关（来源：世界卫生组织《关于身体活动有益健康的全球建议》）。对多数久坐人群，每天 30 分钟快走或慢跑是可行的起点，但亚健康由睡眠、饮食、压力等多因素共同造成，运动是关键一环而非唯一解。

*本次调整：破折号改为逗号；"极其""彻底"等绝对词改为有据表述；补充来源标注；辩证说明多因素。*
